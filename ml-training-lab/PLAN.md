# 8 周学习计划

> 假设：每周投入 6–8 小时（工作日晚上 1 小时 + 周末半天），有工程基础但没模型基础。
> 每一周都有**可验证的验收标准**，做不到就回退，不要往下走。
> 打勾表示完成。每完成一周，在 `notes/` 下留一段自己的话（不写等于没学）。

---

## 第 0 周（半天）：把环境跑通

- [ ] 跑完 `code/01` `02` `03` `04`，四个脚本都能出结果
- [ ] 改 `labkit.build_dataset(impressions_per_user=20)`，重跑 01 和 04，记录 AUC 变化
- [ ] 读 `notes/00-知识地图.md`，把不认识的术语圈出来

**验收**：能用自己的话说清楚 —— 「训练一个模型」到底在优化什么？为什么用 logloss 而不是准确率？

---

## 第 1 周：建立核心直觉

- [ ] 手改 `01_lr_baseline.py`：把 `C` 从 0.5 调到 0.01 / 10，看 AUC 和校准怎么变
- [ ] 手改 `features.py`：去掉 `user_cat` 交叉特征，看 AUC 掉多少（这就是"特征交叉"的价值）
- [ ] 读完 Karpathy《Deep Dive into LLMs》前 1 小时（建立"模型是在学数据分布"的直觉，可与 CTR 对照）
- [ ] 读 `notes/01-CTR模型演进.md`，画出自己能讲出来的演进图

**验收**：能解释「为什么 LR 在这个数据上只有 0.70，而天花板是 0.795」，并指出缺的是哪类信息。

---

## 第 2 周：特征工程与防泄漏（最关键的一周）

- [ ] 在 `features.py` 里新增 3 个因果特征（例：用户近 1h 曝光数、商品价格分桶、用户对类目的历史 CTR）
- [ ] 每个新特征都要在 valid 上验证「有没有用」，记录提升幅度
- [ ] 跑 `03_leakage_lab.py`，然后**自己再制造一个泄漏**（提示：用 test 窗口的商品曝光次数）
- [ ] 读 `notes/02-训练排障手册.md`，把「AUC 突然暴涨」那一节抄进自己的 checklist

**验收**：能说出「这个特征在预测那一刻算得出来吗」并给出 3 个真实判断例子；知道 point-in-time join 是什么。

---

## 第 3 周：GBDT 与调参方法论

- [ ] 跑 `02_gbdt.py`，理解为什么用 valid 而不是 test 选超参
- [ ] 把 `leaves` 网格扩到 `[15, 31, 63, 127, 255]`，画出「叶子数 vs AUC」的曲线，找到拐点
- [ ] 把 GBDT 的特征重要性排序，和 LR 的权重排序对比，解释差异
- [ ] 试一次 `brew install libomp` + 真 LightGBM，对比和 sklearn 版本的差异

**验收**：能画出「过拟合曲线」（训练集 AUC 涨、valid AUC 掉）并解释原因；知道 early stopping 在防什么。

---

## 第 4 周：神经网络与 embedding

- [ ] 跑 `04_deepfm.py`，逐行读懂 `DeepFM.forward()` 的四步
- [ ] 做三个消融实验，各记录 AUC：
  - [ ] 去掉 FM 二阶项（只留一阶 + DNN）
  - [ ] 去掉 DNN（只留 FM）
  - [ ] embedding 维度从 16 改成 4 / 64
- [ ] 把 `dim` 和 `weight_decay` 做成命令行参数（`argparse`），跑 6 组组合
- [ ] 观察：`impressions_per_user=8` 和 `20` 下，DeepFM 相对 GBDT 的优势怎么变

**验收**：能解释 embedding 为什么能"吃下" 1.2 万个 user_id 而 GBDT 不能；知道 embedding 表的显存怎么算
（`基数 × 维度 × 4 字节`，1.2 万 × 16 × 4 ≈ 0.8MB，所以线上几亿 ID 才是真问题）。

---

## 第 5 周：序列建模（DIN）

- [ ] 读 DIN 论文（Deep Interest Network, Alibaba 2018）第 3–4 节，只看结构和动机
- [ ] 在 `labkit.py` 里给每个用户造「历史点击序列」（注意：只能用当前行之前的行为）
- [ ] 在 `04_deepfm.py` 基础上加一个 attention：`score(候选商品, 历史商品)` → 加权求和
- [ ] 对比有无 attention 的 AUC

**验收**：能讲清楚「为什么用户历史行为的加权方式，比历史行为的平均值更有信息量」；
attention 的 Q/K/V 在这个场景里分别对应什么。

---

## 第 6 周：多目标与校准

- [ ] 造第二个 label（比如"是否购买"，由点击率再乘一个转化率生成）
- [ ] 用两个独立模型分别预测点击/购买，再手写一个加权融合 `pCTR^a * pCVR^b * price`
- [ ] 了解 MMoE 的动机（任务相关性 vs 冲突），不必实现
- [ ] 对 `04` 的输出做一次校准（`sklearn.calibration.IsotonicRegression`），比较 LogLoss
- [ ] 读 `notes/03-指标体系与线上.md`

**验收**：能解释「AUC 涨了但收入可能下降」的三种机制（校准、多目标权重、生态效应）。

---

## 第 7 周：工程化（你的主场）

- [ ] 把四个脚本抽成一个 `pipeline.py`：读配置 → 造特征 → 训练 → 评估 → 存模型
- [ ] 模型持久化：把 vocab、均值方差、模型权重存成一份 artifact，写一个 `predict.py` 加载它
- [ ] 写一个「训练-推理一致性」测试：同一批样本，离线打分和加载 artifact 后打分必须一致
- [ ] 估算服务成本：QPS × 特征维度 × 模型大小，讲清楚瓶颈在哪
- [ ] 了解 AUC 的置信区间怎么算（bootstrap），给 test AUC 加一个 ±范围

**验收**：能画出「离线训练 → 模型发布 → 在线打分 → 日志回流 → 再训练」的完整闭环，
并指出每一环最容易出错的地方（答案在 `notes/03` 里）。

## 怎么判断自己真的入门了

能独立回答下面 6 个问题，就算过关：

1. 为什么训练集/测试集要按时间切？随机切在什么情况下会骗你？
2. AUC 0.72 和 AUC 0.75 的差别，在业务上意味着什么？怎么换算成 RPM？
3. 模型离线 AUC 涨了 0.005，线上 A/B 没动静，列出 5 个可能原因。
4. 一个 1.2 万取值的 ID 特征，LR / GBDT / DeepFM 分别怎么处理？代价是什么？
5. 为什么用 logloss 训练，却用 AUC 评估？两者什么时候会打架？
6. 用户历史行为序列长度从 10 加到 100，收益和成本分别在哪？
