# 01 · CTR 模型演进

一条主线：**每一代都在补上一代"表达能力不够"的短板，代价是更高的计算和工程成本。**
看懂这条主线，你就能在任何一篇新论文里快速定位「它补的是哪块」。

---

## 第 1 代：LR + 人工交叉特征（2007–2013）

```
score = w0 + Σ wi·xi        p = sigmoid(score)
```

- **能表达**：每个特征独立的线性贡献
- **不能表达**：特征组合。而"男性 × 游戏类目"才是 CTR 的关键信息
- **工程解法**：人工造交叉特征，再把交叉特征 one-hot 进去

**代价**：交叉特征数量随特征数平方增长。1 万个特征两两交叉就是 5000 万维，
存储和更新都扛不住。这就是 FM 要解决的问题。

---

## 第 2 代：GBDT + LR（Facebook, 2014）

```
原始特征 ──► GBDT（几百棵树）──► 每棵树的叶子编号 ──► one-hot ──► LR
```

- GBDT 负责**自动做特征组合和非线性切分**，LR 负责**快速打分和校准**
- 工程上非常香：GBDT 可以离线预训练，线上只跑 LR，延迟极低
- 至今仍是很多公司的 baseline 和兜底方案

**代价**：GBDT 学到的组合是"离散的、不可微的"，无法端到端优化；
且树模型吃不下高基数 ID（我们 `02_gbdt.py` 里就丢掉了 `user_id`）。

---

## 第 3 代：FM / FFM（2010 / 2016）

FM 给每个特征学一个隐向量 `v_i`，用内积表示交叉：

```
ŷ = w0 + Σ wi·xi + Σ_{i<j} <v_i, v_j> · xi·xj
```

**为什么这是关键一步**：即使「用户A × 类目B」这个组合在训练集里从没出现过，
只要用户 A 和类目 B 各自有向量，内积就能算出它们的匹配度 —— **泛化能力**。

数学上有个技巧让计算量从 O(n²) 降到 O(nk)：

```
Σ_{i<j}<vi,vj>xi xj = 0.5 · [ (Σ vi xi)² − Σ (vi xi)² ]
```

这就是 `04_deepfm.py` 里 `forward()` 第 3 步那两行代码。

**FFM** 进一步给每个特征按"对方字段"学多组向量（field-aware），效果更好、参数更多。
**代价**：参数量 = 特征数 × k，线上几亿 ID 时 embedding 表本身就是主要内存开销。

---

## 第 4 代：DeepFM（华为, 2017）

```
        ┌── FM 部分（一阶 + 二阶）──┐
输入 ───┤                            ├──► sigmoid
        └── DNN 部分（高阶非线性）──┘
              ↑ 共享同一套 embedding
```

- 把 FM 和 DNN **并联**，共享 embedding 表
- FM 负责低阶交叉（显式），DNN 负责高阶交叉（隐式），一次训练同时得到
- **不需要人工造交叉特征**，端到端

这是本仓库 `04_deepfm.py` 实现的版本。它的三个部件对应三种能力：

| 部件 | 能力 | 代码 |
|---|---|---|
| 一阶（`lin`） | 每个字段自己的权重，等价于 LR | `first` |
| FM（`second`） | 两两字段的隐向量内积 | `0.5*(s*s - e²)` |
| DNN | 三阶及以上的隐式交互 | `self.dnn(...)` |

## 第 5 代：DIN / DIEN（阿里, 2018 / 2019）

**问题**：用户历史点击过 100 个商品，直接把平均向量喂给网络，会丢掉"当前候选商品和历史上哪个最相关"。

**DIN 的做法**：用 attention 加权求和

```
v_user = Σ_i a(candidate, item_i) · e_i
```

- 候选是"奶粉"，历史里的"尿不湿"权重高，"手机"权重低
- 这就是「**用户兴趣是局部激活的**」这个业务洞察的模型化

**DIEN** 再加一层 GRU 建模兴趣的**演化**（兴趣漂移）。

**代价**：线上要实时取用户行为序列，特征工程和存储成本大幅上升（这是工程活）。

---

## 第 6 代：显式高阶交叉 —— DCN-v2（2020）

FM 只能到二阶。DCN 用 cross network 显式构造任意阶交叉：

```
x_{l+1} = x0 ⊙ (W x_l + b) + x_l
```

和 DeepFM 并联（DCN-v2 的 "parallel" 结构），现在很多大厂精排的主力结构之一。

---

## 第 7 代：多目标 —— MMoE / PLE（2018–2020）

**问题**：只优化点击，模型会推「标题党」；业务要的是点击 × 转化 × 成交 × 时长。

**MMoE**：多个专家网络 + 每个任务一个 gate，任务之间共享 + 隔离：

```
task_k 输出 = Σ_i gate_k(x)_i · expert_i(x)
```

**PLE** 进一步解决「任务冲突」（比如点击和退货率负相关），加分层专家隔离。

**工程重点**：多目标的**融合公式**（`pCTR^a × pCVR^b × price`）比模型结构更影响最终收入，
而且系数要靠线上 A/B 调，离线 AUC 帮不上忙。

---

## 第 8 代：序列建模 / 生成式（2022–2026）

- **HSTU（Meta, 2024）**：把推荐完全当成序列生成任务，用 Transformer 直接建模
  用户行为序列，验证了推荐系统也存在 **scaling law**（模型越大、数据越多，效果越好）
- **生成式推荐**：一次前向直接生成候选，替代「召回 → 粗排 → 精排」的多级漏斗
- **LLM4Rec**：用 LLM 的语义理解做冷启动、跨域迁移；或用 LLM 生成用户画像当特征

对个人学习者的意义：**这套东西的工程门槛很高**（千卡 + 海量日志），
但它的思想（序列 + 注意力 + scaling）值得理解，因为它正在改变"推荐模型长什么样"。

## 一张表总结

| 年代 | 模型 | 补的短板 | 新增成本 |
|---|---|---|---|
| 2007 | LR + 人工交叉 | 基线 | 人工特征工程 |
| 2014 | GBDT + LR | 自动特征组合 | 两阶段，不能端到端 |
| 2010 | FM | 稀疏交叉的泛化 | 参数量 = 特征数 × k |
| 2017 | DeepFM | 高阶 + 低阶一次搞定 | 训练变慢，需要调参 |
| 2018 | DIN | 用户兴趣局部激活 | 实时行为序列 |
| 2020 | DCN-v2 | 显式高阶交叉 | 结构复杂，收益边际 |
| 2020 | MMoE / PLE | 多目标 | 融合系数难调 |
| 2024 | HSTU / 生成式 | 全局序列建模 | 算力 + 数据规模 |

## 选型建议（电商场景）

| 位置 | 常用结构 | 关键约束 |
|---|---|---|
| 召回 | 双塔（user tower / item tower）+ 向量检索 | 延迟 < 10ms，向量要能离线建索引 |
| 粗排 | 轻量双塔 / 蒸馏后的小模型 | 几百个候选，延迟 < 20ms |
| 精排 | DIN / DCN-v2 / 多目标 MMoE | 特征最全，延迟 < 50ms |
| 重排 | 规则 + 多样性 + 业务约束 | 不追求 AUC，追求生态指标 |

**新手上手顺序**：从精排的 LR baseline 开始（本仓库 `01`），
再往 DIN 走（`PLAN.md` 第 5 周）。召回是另一个体系（向量检索、ANN），先别碰。

## 一个反直觉的事实

在同一份数据上，本仓库三个模型的 AUC 是 **0.708 / 0.718 / 0.722**，
天花板 0.795。模型结构从线性爬到神经网络，只拿到 0.014。

**这不是模型没用，而是"特征的信息量决定了上限"。**
工业界真正的差距来自：用户行为序列长度、实时特征新鲜度、跨域数据、样本质量。
所以如果你只有时间做一件事，去做特征和样本，别去调网络结构。
