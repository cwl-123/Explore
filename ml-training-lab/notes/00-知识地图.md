给工程师的版本：少讲数学，多讲「这东西在系统里对应什么」。

---

## 1. 训练到底在干什么

一句话：**在参数空间里找一组数，让模型在数据上的预测尽量准。**

```
数据 (x, y)  ──►  模型 f(x; θ)  ──►  预测 p  ──►  损失 L(p, y)  ──►  梯度下降更新 θ
```

三个要素，缺一不可：

| 要素 | 你每天要面对的问题 | 工程类比 |
|---|---|---|
| 数据 | 样本怎么造？标签准不准？有没有泄漏？ | 输入契约 + 数据质量 |
| 模型 | 用 LR 还是 DeepFM？特征怎么进？ | 选架构（和选数据库一样，看场景） |
| 目标函数 | 用 logloss 还是 AUC 近似？要不要加正则？ | 系统的「优化目标」定义 |

**训练不是魔法，是一个最优化问题**。你在工程里遇到的一切现象（loss 不降、过拟合、
显存爆、慢），都能从这三个要素里找到原因。

### 为什么是 logloss 而不是准确率

- 准确率对参数不可导（0/1 阶跃），没法做梯度下降
- 准确率不区分「预测 0.51」和「预测 0.99」，但广告出价需要知道**有多确定**
- logloss 来自极大似然估计，它惩罚「自信地错」远大于「犹豫地错」

直觉：`L = -[y·log p + (1-y)·log(1-p)]`。预测 0.9 但实际是 0，损失 2.3；
预测 0.51 实际是 0，损失 0.71。**所以模型会学得"不敢乱自信"** —— 这正是校准的来源。

## 2. 五个必须建立的直觉

**① 模型是参数化函数，训练是下山**
学习率 = 步长；batch = 每次看多少样本估一次梯度；epoch = 把数据过几遍。
学习率太大 → 跳过谷底（loss 震荡/发散）；太小 → 走不到（训练慢，停在半山腰）。

**② 泛化 ≠ 记忆**
训练集 AUC 0.95、测试集 0.70 = 模型把训练集背下来了。
判断方法：看两条曲线是否分叉。分叉了就该加正则、减容量、加数据、早停。

**③ 特征比模型重要（在 CTR 里尤其如此）**
本仓库实测：换模型结构（LR → GBDT → DeepFM）只从 0.708 爬到 0.722，
而天花板是 0.795。**剩下的 0.07 全在特征里**（用户行为序列、实时特征、跨域信息）。
业界共识：结构创新换千分位，特征/样本换百分位。

**④ 指标只是代理，不是目的**
AUC 代理的是「排序能力」，线上真正要的是 RPM/成交。代理指标涨了、目标没涨，
是常态（见 `03-指标体系与线上.md`）。

**⑤ 离线 ≠ 线上**
离线是一个静态数据集，线上是一个会反馈、会漂移、有延迟的系统。
两边不一致的原因有六类，见 `03-指标体系与线上.md`。

## 3. CTR 模型 vs 大语言模型

这两个词经常被混着说，其实是两个物种。唯一的共同点是「都用梯度下降」。

| | CTR 模型（推荐/广告排序） | LLM |
|---|---|---|
| 任务 | 二分类：会不会点 | 自回归：下一个 token |
| 标签 | 埋点行为（点击/不点击） | 文本自身（自监督） |
| 输入 | 高维稀疏特征：ID、类目、时间、上下文 | token 序列 |
| 数据量 | 千万～百亿行，每行几十个特征 | 万亿 token |
| 模型规模 | 百万～几亿参数 | 十亿～万亿 |
| 结构 | Embedding + 特征交叉 + MLP | 纯 Transformer |
| 训练成本 | 单机多卡，小时级 | 千卡，月级 |
| 瓶颈 | **特征工程、样本、线上一致性** | **数据质量、算力** |
| 指标 | AUC / LogLoss / GAUC | 困惑度 / benchmark |
| 失败模式 | 特征泄漏、训练服务不一致 | loss spike、灾难性遗忘 |

**对你（电商策略算法）意味着什么**：主线是左列，把左列吃透就够干很久。
右列现在的位置是「当特征提取器」或「做文本理解类子任务」，不是替代排序模型。

两者的边界在变模糊：Meta 的 HSTU 把推荐当序列生成任务、用 Transformer 做排序，
2024 年后「生成式推荐」成为主流研究方向。但那是第 8 周之后的事。

## 4. 术语表（工程师版）

| 术语 | 一句话解释 | 工程里的等价物 |
|---|---|---|
| label / 样本 | 一条「(特征, 答案)」记录 | 一条训练数据 |
| embedding | 把稀疏 ID 映射成低维稠密向量，向量可学习 | 一张可训练的哈希表，`id → float[k]` |
| 特征交叉 | 两个特征的组合（用户 × 类目） | 联合索引 / 复合 key |
| OOV | 没见过的 ID（线上新用户/新商品） | 缓存未命中，必须有兜底 |
| 过拟合 | 训练集上很好，新数据上很差 | 把测试数据写死进代码 |
| 正则 / dropout | 限制模型记住细节的能力 | 限流/降级，防单点过载 |
| early stopping | valid 指标不涨就停 | 熔断 |
| 校准 (calibration) | 预测 0.1 的那批样本，真实点击率也应该是 0.1 | 监控告警阈值要准，不只是排序对 |
| AUC | 随机取一正一负，正样本得分更高的概率 | 排序能力的单一数字 |
| GAUC | 按用户分组算 AUC 再加权平均 | 「同一用户内部排序」的能力 |
| LogLoss | 概率预测的交叉熵 | 概率准不准 |
| 特征穿越 / 泄漏 | 特征里混进了预测时刻拿不到的信息 | 读到了未来的数据 |
| point-in-time join | 只能用 `t` 之前的快照拼特征 | 时间旅行禁止 |
| training-serving skew | 离线特征和线上特征算得不一样 | 同一份逻辑两份实现，必然分叉 |
| position bias | 位置靠前更容易被看到（不是被喜欢） | 曝光位是资源，不是质量 |
| 冷启动 | 新用户/新商品没历史 | 无历史数据的兜底策略 |
| 多目标 | 同时优化点击/转化/时长 | 多个 SLO 相互冲突 |
| 增量/在线学习 | 模型随新数据持续更新 | 热更新，而不是重新发布 |

## 5. 推荐材料（按优先级）

**必看（本仓库之外）**

1. 《Deep Interest Network for Click-Through Rate Prediction》(Alibaba, 2018)
   —— 排序模型的分水岭，讲清楚「用户行为序列怎么用」。读第 3–4 节即可。
2. 《Deep Learning for Recommender Systems》相关综述，或王喆《深度学习推荐系统》
   —— 中文，工程视角，把 LR→FM→DIN 的演进讲得很清楚。
3. [Karpathy: Deep Dive into LLMs](https://www.youtube.com/watch?v=7xTGNNLPyMI)
   —— 不是讲 CTR 的，但能帮你建立「模型在学数据分布」的通用直觉。
4. [Stanford CS336](https://stanford-cs336.stanford.edu/) Lecture 1–2
   —— tokenization + 资源估算（显存/FLOPs 怎么算），对工程背景的人极其友好。

**想动手做大一点**

- Criteo 数据集（Kaggle 2014 Display Advertising Challenge，约 11GB）：真实 CTR 数据，练全流程
- [FuxiCTR](https://github.com/reczoo/FuxiCTR)：主流 CTR 模型的统一实现，适合对照阅读
- [torch-rechub](https://github.com/datawhalechina/torch-rechub)：中文教程 + 模型实现

**不建议一开始就看的**

- 《深度学习》花书（数学太重，先跑通再补）
- 一上来读 Transformer 原论文（先把 embedding + FM 搞明白）

## 6. 学习顺序（为什么是这个顺序）

```
LR（理解"线性打分 + logloss"）
  └─► 特征工程 + 防泄漏（工程能力，收益最大）
        └─► GBDT（非线性 + 调参方法论）
              └─► DeepFM（embedding + 交互，理解"为什么需要神经网络"）
                    └─► DIN（序列建模，工业界主力）
                          └─► 多目标 / 校准 / 生成式
```

每一层都在回答上一层的短板：LR 学不到交互 → 加交叉特征 → 交叉爆炸 → embedding；
树模型吃不了高基数 ID → 用统计特征替代 → 丢失个性化 → embedding 补回来。

**跳步的代价**：直接上 DeepFM，你会调不出效果，因为你不知道问题出在特征还是结构。
先把 LR 跑到天花板附近，再往上加复杂度，每一步的收益才看得见。
